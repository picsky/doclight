## 0. 一句话定位

**部署与分发不是技术功能的补充，是产品从「文档站工具」升级为「内容价值兑现平台」的钥匙。**

用户的底层动机不是「做文档站」，而是「**让内容被理解、被信任、被传播**」。文档站只是达成这个目的的中介。部署是内容价值的兑现，分发是理解发生的最后一公里。

## 1. 动机链与使用场景

### 1.1 动机链

```
写内容（Why create）
   │  自我备忘 · 交付沟通 · 建立权威 · 变现 · 知识沉淀
   ▼
部署成站（Why publish）
   │  内容价值的兑现：不被看到 = 不存在
   │  · 可访问（一个 URL/文件，点开即看）
   │  · 可发现（SEO / AI agent 检索）
   │  · 可信赖（排版精良 → 读者信任）
   │  · 可维护（Git 版本 / 持续更新）
   ▼
分发传播（Why share）
   │  理解发生的最后一公里
   │  · 链接给一个人 / 一群人 / 全世界
   │  · 被收藏、被转载、被 AI 引用
```

### 1.2 使用场景矩阵（结合 research §2.1 personas）

| Persona | 做内容动机 | 部署动机 | 分发方式 | 分发目标 |
|---|---|---|---|---|
| **P1 个人开发者/开源维护者** | 记录 + 项目信誉 | 文档被看见、被 fork | GitHub Pages URL | 贡献者 + 用户 |
| **P2 技术写作者** | 交付团队文档 | 编辑即发布，非开发者可用 | 链接 + 团队共享 | 团队 + 客户 |
| **P3 自托管/homelab** | 数据自主、隐私 | 不依赖第三方，自己掌控 | 自有域名/NAS | 自己 + 少数人 |
| **P4 小团队（2-15人）** | docs-as-code、版本控制 | 性价比、零维护 | 链接 + 嵌入官网 | 客户 + 用户 |
| **P3′ 课程作者（空白细分）** | 卖课/教学 | 学员轻松看课 | 链接/文件/平台 | 学员 |

**核心发现**：
1. **「给别人看」是压倒性的部署动机**——除自我备忘外，几乎所有人部署都是为了给特定对象看
2. **分发目标决定形态**：给全球看 → SSG+托管；给团队看 → URL；给无技术环境的学员/客户看 → **bundle 单文件**
3. 三形态天然对齐三种「给别人看」的规模，但要讲成**分发能力**而非技术形态

### 1.3 分发目标 → 形态映射

| 受众规模 | 分发场景 | 推荐形态 | 分发手段 |
|---|---|---|---|
| 全球 | 公开文档、产品站、博客 | ② SSG | 链接 + SEO + AI 检索 |
| 团队/组织 | 内部知识库、交付文档 | ② SSG / 托管 | 链接 + 嵌入 |
| 个人/小群 | 课程学员、客户、好友 | ③ bundle | 文件 + 二维码 |
| 自己 | 本地笔记、预览 | ① dev / bundle | 本地访问 |

## 2. 部署分层（把摩擦降到「顺手」）

| 层级 | 形态 | 用户心智 | 一句话 | 对应动作 |
|---|---|---|---|---|
| **零部署** | ③ bundle | 「发给对方就完事」 | 不用托管，一个文件即达 | `doclight bundle` → 发文件 |
| **轻部署** | ② SSG | 「一条命令上线」 | 免费托管，push 即发布 | `doclight build` + `doclight deploy` |
| **托管部署** | 未来 SaaS | 「我不管技术」 | 对标 Mintlify 但扁平定价 | 拖拽/同步即发布（非 MVP） |

### 2.1 `doclight deploy` 命令（轻部署核心）

> **背景**：research 显示 41% 无文档团队的组织没上任何工具，最大拦路虎不是「写」而是「发布」这套工程流程。一键部署是对此的直接回应。

```bash
doclight deploy                # 自动检测并部署到支持的平台
doclight deploy --platform gh-pages
doclight deploy --platform cloudflare-pages
doclight deploy --platform netlify
```

**行为设计**：
1. 自动检测 git 仓库与远程（无则提示 `doclight init` 引导）
2. 构建（复用 `build`）→ 生成静态产物
3. 平台适配：GitHub Pages（创建/更新分支 + Actions 配置）/ Cloudflare / Netlify（检测账号或输出部署包）
4. 输出：**最终 URL**（可访问即成功）+ 分享卡片（见 4.2）
5. 失败：结构化错误 + 人工步骤指引

**原则**：deploy 是 `build` 的延伸，不引入新概念；默认路径零配置可用。

## 3. 分发四触点

现有设计完全未覆盖的四个分发能力：

| 触点 | 能力 | 说明 | 落地 |
|---|---|---|---|
| **链接分发** | 唯一 URL | SSG 天然支持 | ✅ 已有 |
| **文件分发** | bundle 单文件 | 微信/网盘/邮件直接发 | ✅ 已有（5.3.4） |
| **嵌入分发** | iframe 代码 | 一键生成 `<iframe>`，嵌进语雀/飞书/博客/官网 | 🆕 需新增 |
| **社交分发** | OG 分享卡片 | 链接发到微信/X 时显示精美卡片（标题/摘要/预览图） | 🆕 需新增 |

### 3.1 嵌入分发（iframe）

- `doclight embed` 命令：构建后生成 `snippet.js`（自动注入 iframe + 响应式）
- 或提供可复制的 `<iframe src="...">` 代码块（带尺寸自适应）
- 场景：嵌入团队 wiki、官网、课程平台、博客正文

### 3.2 社交分发（OG 分享卡片）

- SSG 构建时自动生成**每页 OG 图**（当前仅有 OG 标签，无图片）
- 卡片内容：页面标题 + 站点名 + 主题色背景 + 站点 Logo（符合模板视觉）
- 生成方式：Node 侧用 canvas/svg 渲染静态图（无浏览器依赖）
- 价值：链接被分享到微信/微博/X/钉钉时，精美卡片 = 点击率提升 = 传播裂变开关

## 4. 传播机制（让文档站自己获客）

research §3.2 说迁移靠「逃难指南」获客，但**文档站本身应成为获客工具**：

| 机制 | 设计 | 说明 |
|---|---|---|
| **Powered by DocLight** | 站点底部默认一个可关闭的小标记 | 口碑裂变；对比：docsify 未做，GitBook 隐晦 |
| **分享即预览** | 复制链接时附 OG 卡片，分享动作自带吸引力 | 与 3.2 协同 |
| **SEO + AI 双可发现** | SSG 产物天然 SEO；llms.txt/MCP 让 AI 可检索 | 「被 AI 推荐」是新增长通道 |
| **主题画廊营销页** | `doclight preview --themes` 画廊页可公开部署 | 「工具做出的站长这样」的活广告 |

> Powered by 默认开启、可一行关闭；不强制（尊重 P3 自托管用户的数据洁癖）。

## 5. 中文市场分发设计（research 的空白机会）

现有设计严重低估中文市场分发差异：

| 维度 | 国外 | 中文市场 |
|---|---|---|
| 开发者分发 | GitHub Pages + X/Reddit | Gitee Pages + 公众号/知乎/B站 |
| 非开发者分发 | email + Dropbox | **微信 + 网盘**（文件即分发） |
| 课程分发 | 平台托管 | **公众号 / 网盘 / 课程平台** |
| 技术门槛容忍 | 较高 | **极低**（课程作者最怕命令行） |

**核心机会**：bundle 单文件是**唯一契合中文「发文件」分发习惯的形态**——doclight.html 经微信/网盘发给学员或客户，对方双击即得精美文档站。国外工具在中文非开发者市场完全失效。

**中文市场补充能力**：
1. **下载二维码**：bundle 构建后生成二维码（手机扫码 → 下载/打开文档）
2. **移动端重点打磨**：学员多数用手机看课，bundle 移动端体验是一等公民
3. **文档里嵌入提示**：bundle 首屏可显示「这是一份离线文档，可转发」的引导（可选）

## 6. 场景泛化路线（超越「文档站」）

如果「Markdown → 美丽可分享产物」足够顺滑，使用场景自然泛化：

| 泛化场景 | 说明 | 契合形态 | 优先级 |
|---|---|---|---|
| **讲义/报告** | 课程讲义、调研报告 | SSG / bundle | ★★★ |
| **AI 生成内容展示** | AI 写的教程/报告 → 一键渲染成站 → 一键发布 | 全部 | ★★★ |
| **产品发布页/落地页** | 非技术用户的营销场景 | SSG / bundle | ★★ |
| **作品集/个人主页** | markdown 驱动的个人站点 | SSG | ★★ |
| **电子书/白皮书** | 长内容精排 + 可分发 | bundle | ★ |
| **团队知识库** | 内部 wiki（P4 场景） | 托管/SSG | ★ |

**最具想象力的闭环**：AI 生成内容 → `doclight bundle/build` → 一键发布。**DocLight 是 AI 生成内容的消费载体**——这比「文档站工具」的定位大得多，也直接呼应 Agent-First 原则：产品既是「给人看的文档站」，也是「AI 产物的展示层」。
