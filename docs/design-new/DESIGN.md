# Aster 设计纲领（Design Constitution）

> 本文档是项目视觉与交互设计的最高准则。它的目标不是记录"现在长什么样"，
> 而是保证**三年后由不同的人做出的新页面，看起来仍像同一个产品**。
>
> 使用方法：新增任何界面之前读第 1、2 章；写代码时查第 3、4 章；
> 提交前过一遍第 8 章检查清单；想修改本文件本身时读第 9 章。

---

## 1. 设计哲学（Why）

五条第一原则。当具体规则之间冲突时，回到这里裁决。

### 1.1 排版即界面（Typography is the interface）
信息层级首先由**字重、字号、字距、留白**构建，而不是色块、卡片和阴影。
一个页面如果去掉所有颜色和边框后层级依然清晰，它才是合格的。
颜色是最后一层增强，不是第一层手段。

### 1.2 克制即丰富（Restraint is richness）
每加一个视觉元素，必须回答："它帮助用户理解什么？"
答不上来就删掉。空白不是浪费，是呼吸。
**默认不加**：渐变、玻璃拟态、投影堆叠、圆角加大、装饰性插画、动画。

### 1.3 颜色有职务，不做装饰（Color has a job）
全产品只有**一个强调色**，且只出现在功能性位置：
链接、激活态、焦点环、关键状态。看到强调色 = 可以交互或正在生效。
装饰性用色一律禁止。中性色承担 95% 的界面。

### 1.4 隐形的基础设施（Invisible infrastructure）
本产品是开发者的基础设施，设计的使命是**让人忘记设计的存在**。
用户读完文档记住的应该是内容，不是界面。
任何"哇这个设计好酷"的瞬间，都是可疑信号。

### 1.5 时间是唯一的测试（Time is the test）
判断一个设计决策时问：**三年后这会显得过时吗？**
流行趋势（新拟态、玻璃拟态、大字标、AI 渐变）天然会过期；
排版秩序、发丝线、克制配色从 1960 年代的瑞士平面设计至今有效。
我们只做后者。

## 2. 美学标准（可检验的判断标尺）

每个界面提交前，用以下问题自检。任何一条答"否"，就打回。

| # | 标准 | 检验问题 |
|---|------|----------|
| 1 | **层级去色测试** | 把界面脑补成纯黑白，信息层级是否依然清楚？ |
| 2 | **强调色审计** | 全页强调色出现的地方，是否个个都是"可交互"或"当前状态"？ |
| 3 | **发丝线测试** | 分隔是否全部用 1px 半透明线，而不是投影或色块？ |
| 4 | **字重预算** | 全页字重是否只用了 400/500/600/700 中的 ≤3 档？ |
| 5 | **圆角一致** | 圆角是否全部来自 token（8/10px），没有随手写的 13px？ |
| 6 | **动效动机** | 每个动画能否说清它引导了什么注意力？时长是否 ≤300ms（入场除外）？ |
| 7 | **暗色重设计** | 暗色模式是否逐一调校过，而不是反色？纯黑 #000 是否出现 0 次？ |
| 8 | **三年后测试** | 这个元素是不是当前设计社区的流行手法？是 → 删掉或降级。 |

## 3. Design Tokens（唯一事实来源）

所有视觉值必须引用 token，**禁止在组件中硬编码色值、字号、圆角、时长**。
新增 token 需要设计评审（见第 9 章）。

### 3.1 色彩

```css
:root{
  /* 中性色：暖调，避免纯黑纯白（刺眼且廉价感） */
  --bg:            #ffffff;   /* 页面底色 */
  --bg-subtle:     #f7f6f3;   /* 次级底色：表头、tab 条 */
  --surface:       #f0efeb;   /* 控件底色：按钮、行内码 */
  --text:          #1b1b18;   /* 主文字：不是纯黑 */
  --text-2:        #57554e;   /* 次级文字 */
  --text-3:        #6e6b62;   /* 辅助文字：元信息、占位符 */
  --line:          rgba(27,27,24,.08);  /* 发丝分隔线 */
  --line-strong:   rgba(27,27,24,.16);  /* 强分隔线、控件边框 */

  /* 唯一强调色：松绿 Pine。职务 = 链接 / 激活 / 焦点 / 关键状态 */
  --accent:        #14714e;
  --accent-hover:  #0e5a3d;
  --accent-soft:   rgba(20,113,78,.07);  /* 激活态底色 */
}

/* 暗色模式是独立设计，不是反色 */
html.dark{
  --bg:            #111110;   /* 暖黑，禁止 #000 */
  --bg-subtle:     #181816;
  --surface:       #20201d;
  --text:          #ebeae5;
  --text-2:        #a5a29a;
  --text-3:        #9a968c;
  --line:          rgba(235,234,229,.09);
  --line-strong:   rgba(235,234,229,.18);
  --accent:        #63d2a0;   /* 暗色下提亮，保持对比度 ≥ 4.5 */
  --accent-hover:  #85e0b8;
  --accent-soft:   rgba(99,210,160,.10);
}
```

**色彩纪律：**
- 禁止引入第二个品牌强调色。语义色仅三枚：成功 `#3d9e4f`、警示 amber、错误 red，且只用于状态指示（图标、小圆点），不用于大面积填充。
- **强调色与语义绿色的隔离**：松绿强调色与成功绿同处绿色家族，必须双重保险——① 成功态永远以「对勾图标 + 文字」形式出现，颜色只作辅助；② 成功绿取偏黄相（#3d9e4f），与松绿的偏蓝相拉开，两者不得出现在同一组件内。
- 语法高亮调色板须随强调色联动更换（函数色 = 强调色），并按主题重新校准，避免代码块中出现与强调色冲突的「色彩孤岛」。
- 文字对比度：正文 ≥ 7:1（AAA），辅助文字 ≥ 4.5:1（AA）。`--text-3` 不得用于正文段落。
- 浅色模式下投影几乎不用；唯一允许的投影是浮层（弹窗、下拉），用 `--shadow-pop`。

### 3.2 字体与排版

```css
/* 字体栈：Inter 负责拉丁，系统字体负责中文，等宽负责代码 */
--font-sans: "Inter", -apple-system, "PingFang SC", "Microsoft YaHei", sans-serif;
--font-serif: "Source Serif 4", Georgia, "Songti SC", serif;  /* 仅用于引言 */
--font-mono: "JetBrains Mono", ui-monospace, Consolas, monospace;
```

**类型阶（Type Scale）——全产品只允许这几档：**

| 用途 | 字号 | 字重 | 行高 | 其他 |
|------|------|------|------|------|
| 页面标题 H1 | 34px | 700 | 1.2 | 字距 -0.025em |
| 章节标题 H2 | 21px | 650 | 1.3 | 字距 -0.015em |
| 小节标题 H3 | 16px | 600 | 1.4 | 字距 -0.01em |
| 引言 lede | 18px | 400 | 1.8 | 衬线体（唯一的衬线场景） |
| 正文 | 15.5px | 400 | 1.75 | 内容区限宽 700px |
| 次级/辅助 | 12.5–13.5px | 400/500 | 1.5 | --text-2 / --text-3 |
| 标签 eyebrow | 11–12px | 600 | — | 大写、字距 +0.06~0.08em、--text-3 |
| 代码 | 13px | 400 | 1.75 | --font-mono |

**排版纪律：**
- 标题一律开启 `text-wrap: balance`（杜绝孤词行）；正文段落开启悬挂标点。
- 中西文混排时，汉字与拉丁字符/数字之间自动加入发丝空隙（构建期或运行时脚本处理，参考实现见 `index.html`）。
- 数字展示（表格、时间、统计）一律 `font-variant-numeric: tabular-nums`。
- 段落宽度不超过 720px；长文行高不低于 1.7。
- Inter 开启 `font-feature-settings: "cv11","ss01"`（更中性的字形）。

### 3.3 间距、圆角、线条

- **间距**：8pt 网格。组件内边距只许用 4 的倍数（4/8/12/16/24/32/48/64/96）。区块间距用 24/32/44/56。
- **圆角**：仅两档——`8px`（小控件、标签）、`10px`（卡片、代码块、弹层）。头像/徽标可全圆。
- **线条**：分隔一律 `1px solid var(--line)`；控件边框 `1px solid var(--line-strong)`。
  **禁止**用投影做分隔；禁止 2px 以上边框（焦点环除外）。

### 3.4 动效

```css
--ease: cubic-bezier(.22,.68,.2,1);   /* 唯一缓动：快出缓入 */
--dur-fast: .15s;   /* hover、开关 */
--dur: .25s;        /* 颜色、位移、展开 */
--dur-slow: .6s;    /* 页面入场，仅一次 */
```

**动效纪律：**
- 动效的唯一合法理由：**引导注意力**或**维持空间连续性**（这个东西从哪来、到哪去）。
- 交互反馈 ≤250ms；入场编排可错峰（各栏延迟 60ms），总时长 ≤700ms，只发生一次。
- 必须实现 `prefers-reduced-motion` 全量降级。
- 滚动触发的动画只允许"出现一次"，禁止滚动回顶反复播放。

## 4. 组件美学标准

每个组件的存在理由和不可违反项。

### 4.1 导航（侧栏 / 顶栏 / 页内目录）
- 激活态 = 强调色文字 + `--accent-soft` 底色 + 2px 指示线，三选二即可，不要三个都上。
- 分节标题用小型大写字母标签（11px / 600 / +0.08em / --text-3）。
- 顶栏毛玻璃仅在滚动后出现发丝底线，静态时完全隐形。

### 4.2 代码块
- 头部条：文件名（等宽）+ 语言（大写小字）+ 复制按钮（hover 才强调）。
- 语法高亮每主题一调色板，颜色数量 ≤6 种，饱和度宁低勿高。
- 复制成功必须有两秒内恢复的视觉反馈（✓ 已复制）。

### 4.3 表格
- 只有横线，没有竖线；表头用大写小字标签风格；行 hover 给 `--bg-subtle`。
- 数字列右对齐 + tabular-nums；首列标识符用等宽字体。

### 4.4 提示块（Callout）
- 左侧 2.5px 强调色竖线 + 极浅同色系底色，**不加图标彩色徽章**。
- 一个段落只传递一个信息；超过两条就拆成两个 callout 或正文。

### 4.5 图解（Diagram）
- 一律 inline SVG，复用全部 design token（`var(--line-strong)` 等），随主题自动切换。
- 节点 = 白底发丝边框圆角矩形；连线 = 1.2px `--text-3` + 小箭头；标注 = 等宽小字。
- 禁止：立体效果、渐变填充、截图代替、彩色泳道。
- 每张图必须有 `figcaption` 和 `aria-label` 文字等价物。

### 4.6 按钮与输入
- 层级只许三级：实心（每屏至多一个主按钮）/ 描边 / 幽灵。同屏不出现两个实心。
- hover 变化幅度要小：变底色或边框色，**不位移、不放大**（卡片除外，可上浮 1px）。

### 4.7 图标
- 统一线性图标（stroke 1.5–2px、圆角端点），尺寸 12/14/16px 三档。
- 图标永远配文字或 aria-label；不用 emoji 替代图标。

## 5. 中文排版专项

中文是这个产品的一等公民，不是翻译后的补救对象。

1. 中西文之间自动加发丝空隙（盘古之白）；数字与单位之间同样处理。
2. 中文正文不用斜体（斜体是拉丁传统）；强调用**加粗**。
3. 标点一律全角；行首行尾禁则（悬挂标点）必须开启。
4. 中英混排标题里，英文专有名词保持原大小写（"Worker 拉取" 而非 "WORKER 拉取"）。
5. 字号下限：中文正文 ≥14px，辅助文字 ≥12px——中文在更小字号下辨识度骤降。

## 6. 可达性基线（不可妥协）

- 键盘：全站可 Tab 遍历；每个页面有"跳到主要内容"链接；焦点环可见（2px 强调色）。
- 语义：当前页/当前位置标 `aria-current`；图表有 `role="img"` + `aria-label`。
- 动效：`prefers-reduced-motion` 下全部静止。
- 对比度：正文 AAA，辅助 AA，强调色文字两主题下都过 4.5:1。
- 打印：提供 `@media print` 样式（隐藏导航、防跨页断裂、黑白重排）。

## 7. 反模式清单（Never Do）

出现以下任何一条，评审直接打回，不需要讨论：

1. ❌ 新增第二种强调色 / 彩虹渐变 / AI 紫蓝渐变
2. ❌ 纯黑 `#000` 或纯白文字底色对比（暖调中性色是底线）
3. ❌ 用投影做区块分隔（投影只属于浮层）
4. ❌ 硬编码色值/字号/圆角（绕过 token）
5. ❌ 装饰性动画、入场动画每次滚动重复播放
6. ❌ 玻璃拟态卡片、新拟态、大圆角（>12px）面板
7. ❌ 暗色模式用反色/滤镜生成
8. ❌ 中文斜体、中文下划线（下划线 = 链接专用）
9. ❌ 大面积留白处塞装饰插画来"填空"
10. ❌ 追逐当年设计社区的流行风格——这正是本纲领要防御的东西

## 8. 提交前检查清单

```
□ 去掉颜色后层级是否依然成立？
□ 强调色是否只出现在可交互/状态位置？全页 ≤ 合理数量？
□ 所有视觉值是否引用了 token？
□ 字号/字重/圆角/间距是否在批准的档位内？
□ 暗色模式逐项检查过？无纯黑？对比度达标？
□ 中西文混排空隙、tabular-nums、悬挂标点是否生效？
□ 动效 ≤300ms、有动机、reduced-motion 下降级？
□ Tab 键盘走一遍：可达、焦点可见、skip link 正常？
□ Ctrl+P 打印预览是否正常？
□ 三年后测试：这个元素是秩序还是潮流？
```

## 9. 纲领的演进（如何修改本文件）

本文件故意保持稳定。修改规则：

1. **Token 变更**：需走设计评审，说明"旧值出了什么问题"，并全局替换——不允许新旧并存。
2. **新增组件**：先检查能否由现有组件组合而成；确需新增，按第 4 章格式补写"存在理由 + 不可违反项"。
3. **新增原则**：只有当某类设计分歧**反复出现三次以上**，才把裁决结论沉淀为新原则。一次性问题不进纲领。
4. **禁止条款**（第 7 章）只增不减。
5. 每次修改在下方留变更记录，注明日期与理由。
