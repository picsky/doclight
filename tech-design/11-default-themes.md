## 1. 设计原则

### 1.1 为什么是多套完整设计语言

DocLight 的核心卖点是「零配置」，**默认形态就是产品本身**。用户第一次打开看到的界面，决定了要不要继续用。

- ❌ 不是「一套主题 + 换色」——那是敷衍
- ✅ 是 4 套**完整的设计语言**：排版系统、色彩体系、组件风格、动效语言各自独立成立
- 每一套都做到「可以直接放进作品集展示」的水准

### 1.2 四套模板定位

| 模板 | 风格关键词 | 目标人群 | 适用内容 |
|---|---|---|---|
| **Minimal（默认）** | 极简、灰阶、teal | 开发者 / 技术文档 | API、指南、项目文档 |
| **Serif（学术）** | 衬线、纸感、沉稳 | 课程站 / 知识库 | 教程、论文、讲义 |
| **Modern（科技）** | 深色、玻璃、锐利 | Startup / 产品文档 | 产品主页、开发者门户 |
| **Warm（温暖）** | 暖色、圆角、亲和 | 教程 / 个人博客 | 博客、入门教程、社区 |

### 1.3 统一约束（所有模板必须满足）

1. **内容即主角**：所有 UI 服务阅读，装饰性元素为零
2. **中文排版优先**：字号/行高/字距按中文阅读调校（参考 04 文档的排版系统）
3. **亮/暗双主题**：每套模板都提供，且暗色不是亮色的简单反色
4. **无障碍达标**：对比度 ≥ WCAG AA，键盘可操作
5. **响应式三断点**：移动（375）/ 平板（768）/ 桌面（1440）
6. **体积合规**：模板 CSS 全部走 CSS 变量，不显著增加核心体积
7. **主题是 token 层**：模板只覆盖 `theme.json` + CSS 变量 + 少量组件样式，不侵入核心
8. **三形态适配**：模板必须在 dev / SSG / bundle 三种产物形态下表现一致（视觉回归覆盖三形态）

## 2. 模板规格总览

| 维度 | Minimal | Serif | Modern | Warm |
|---|---|---|---|---|
| 主色 | teal `#0d9488` | 深靛蓝 `#1e3a5f` | violet `#7c3aed` | 暖橙 `#d97706` |
| 衬底背景 | 纯白/近黑灰 | 米白纸感 `#faf8f5` | 深黑蓝 `#0b0f19` | 暖米白 `#fdf9f3` |
| 正文字体 | 系统无衬线 | 衬线标题 + 无衬线正文 | 系统无衬线 | 系统无衬线 |
| 标题字体 | 无衬线 | **衬线**（思源宋体/Georgia 栈） | 无衬线（更紧凑） | 无衬线（圆润感） |
| 圆角 | 6px | 2px（克制的） | 8px | 12px |
| 阴影 | 几乎无 | 极浅纸感 | 轻玻璃拟态 | 暖且软 |
| 动效 | 150ms 淡入淡出 | 几乎无动效 | 200ms 微弹性 | 120ms 轻快 |
| 侧边栏 | 灰底细边 | 纸色 | 深色 + 玻璃 | 暖白 |
| 代码块 | 灰阶 | 浅纸色 | 深色玻璃 | 暖灰 |

## 3. 各模板详细规格

### 3.1 Minimal（默认）

**定位**：技术文档事实标准审美。接近 Vercel/Starlight 的克制，但中文排版更考究。

```
设计 token 要点
  --color-primary:       #0d9488  (teal-600)
  --color-bg:            #ffffff
  --color-bg-soft:       #f9fafb
  --color-text:          #374151
  --font-sans:           系统中文栈（PingFang SC / Microsoft YaHei 优先）
  --radius:              6px
  --max-width-content:   680px
```

**特点**：
- 全站唯一彩色是 teal，其余纯灰阶
- 侧边栏：浅灰底、细边框、当前项 teal 高亮
- TOC 导轨：细线 + hover 展开（03 文档的少数派式设计）
- 行内代码用 teal 色（技术文章可读性关键）
- 代码块深一级灰底，圆角统一

**验收锚点**：与现有 [04-reading-experience](./04-reading-experience.md) 的设计 token 完全一致。

### 3.2 Serif（学术）

**定位**：课程站、知识库、长文阅读。纸感 + 衬线标题，读起来像「一本好书」。

```
设计 token 要点
  --color-primary:       #1e3a5f  (深靛蓝)
  --color-bg:            #faf8f5  (米白纸感)
  --color-bg-soft:       #f2efe9
  --color-text:          #3b3a38  (暖墨色)
  --font-serif:          "Noto Serif SC", "Source Han Serif SC", Georgia, serif
  --font-sans:           系统中文栈
  --radius:              2px
  --max-width-content:   720px   (衬线字号小，可略宽)
```

**特点**：
- 标题用衬线字体，正文用无衬线（现代中文学术读物的通行组合）
- 背景是米白纸色而非纯白，文字是暖墨色而非纯黑
- 强调色深靛蓝，克制、安静、有学究气
- 表格只有横线、代码块浅纸色，全站几乎无阴影
- 章节之间的留白更大，强化「书的分篇感」

### 3.3 Modern（科技）

**定位**：Startup 产品文档、开发者门户。深色优先 + 轻玻璃拟态，接近 Mintlify/Linear 的锐利感。

```
设计 token 要点
  --color-primary:       #7c3aed  (violet-600)
  --color-bg:            #0b0f19  (深黑蓝)
  --color-bg-soft:       #111827
  --color-text:          #d4d4d4
  --color-text-strong:   #f5f5f5
  --radius:              8px
  --max-width-content:   720px
```

**特点**：
- **默认暗色**（首次进入即是暗色，可跟随系统切亮色）
- 侧边栏深色 + 轻微玻璃拟态（backdrop-blur 克制使用，仅一层面板）
- 代码块深色玻璃质感，violet 强调色用于链接 hover 与搜索高亮
- 标题更紧凑（行高 1.25），信息密度高
- 动效更活泼（200ms 微弹性），传达「现代产品」气质

### 3.4 Warm（温暖）

**定位**：教程、个人博客、入门课程。暖色 + 大圆角 + 亲和力。

```
设计 token 要点
  --color-primary:       #d97706  (amber-600)
  --color-bg:            #fdf9f3  (暖米白)
  --color-bg-soft:       #f7f0e6
  --color-text:          #4a4238  (暖棕)
  --radius:              12px
  --max-width-content:   680px
```

**特点**：
- 大圆角（12px）+ 暖色系，天然亲和、无距离感
- 提示框 / 代码块都是「卡片感」（浅暖底 + 软阴影）
- 强调色暖橙，用于按钮、链接 hover、当前导航
- 动效轻快（120ms），按钮按压有轻微反馈
- 适合新手向、讲解型内容，弱化「技术文档」的距离感

## 4. 主题预览对比页

**目的**：让用户（和 Agent）能直观对比四套模板，零成本切换。

- `doclight preview` 增加 `--themes` 模式，生成**主题画廊页**
- 画廊页用同一篇示例文档渲染 4 套模板，左右/上下并排展示（亮/暗可切换）
- 是静态 HTML，可部署、可分享、可截图
- 视觉回归基线也取自画廊页（4 模板 × 亮暗 × 断点）

**示例文档**（画廊内容）内置在 CLI：含标题层级、代码块、表格、提示框、公式、图表、引用，覆盖全语法特性。

## 5. 模板的 Agent 友好要求

模板本身也是「为 Agent 设计」的产物：

| 要求 | 说明 |
|---|---|
| **theme.json 可读** | 每个模板有结构化 `theme.json`，字段语义明确，Agent 能读能改 |
| **变量即接口** | 模板只依赖 `--color-*` / `--font-*` / `--radius-*` 等公开 token，不依赖私有类 |
| **脚手架生成** | `doclight theme new` 生成模板骨架，注释即文档 |
| **自动截图** | Agent 可一键生成某模板 × 某断点的截图自审 |
| **合规自动检查** | 设计合规脚本校验每个模板（对比度/间距/节奏），Agent 改完跑一遍即知是否合规 |

## 6. 验收标准

### 视觉验收（机器化）

| # | 验收项 | 验证方式 |
|---|---|---|
| 1 | 4 模板 × 亮暗 × 3 断点共 24 组截图 | 视觉回归 diff = 0 |
| 2 | 各模板对比度达标 | 设计合规检查 |
| 3 | 间距符合 8pt 网格 | 设计合规检查 |
| 4 | 字号节奏（模块化缩放 1.25） | 设计合规检查 |
| 5 | 画廊页可构建、可部署 | `doclight preview --themes` |
| 6 | 模板切换零配置生效 | 行为测试 |

### 设计验收（评审 Agent + 人工兜底）

- 评审 Agent 按「内容是否被 UI 抢戏 / 中文排版是否舒适 / 是否符合模板定位」维度给出 findings
- 最终基线由人一次性确认后锁定，后续仅允许机器可验证的微调

### 性能验收

| 指标 | 目标 |
|---|---|
| 模板 CSS 增量 | 每模板 ≤ 2KB gzip（不显著膨胀核心） |
| 切换模板 | 无 JS 构建，仅换 token 文件 |

## 7. 落地建议（Phase 顺序）

| 阶段 | 模板 |
|---|---|
| Phase 1 内核 | **Minimal** 先行（与内核同步打磨，作为 Golden Master 基线） |
| Phase 2 体验 | Warm（移动端验证场景） |
| Phase 3 SSG | Serif（验证同构渲染对衬线/纸感的支持） |
| Phase 4 AI 就绪 | Modern（验证暗色默认 + 玻璃拟态在 SSG 下表现） |
| Phase 5 生态 | 三套开放为主题包规范案例，模板市场 |
