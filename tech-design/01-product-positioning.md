# 01 · 产品定位与设计哲学

---

## 1.1 产品定位

### 一句话定位

DocLight 是一款**服务于人阅读、同时 AI 原生友好**的零构建开源文档站引擎。

### 定位三角

```
          零构建简单
         /          \
        /            \
  人阅读极致 ——————— AI 原生友好
```

三者缺一不可：
- 只有「零构建简单」→ 是 docsify，有 SEO 死穴、生态弱
- 只有「人阅读极致」→ 是 VitePress/Starlight，需要构建链、有学习成本
- 只有「AI 原生友好」→ 是 Mintlify，SaaS 锁定、定价悬崖、开发者不信任

DocLight 是三者的交集。

### 「零构建」的定义（2026-08 技术验证后重述）

> 浏览器安全模型禁止 JS 在 `file://` 协议下动态读取本地文件（Chromium/WebKit 实测均失败，仅 Firefox 允许）——因此「双击 index.html 动态读 docs/」在主流浏览器上**技术上不可能**。DocLight 的零构建**不是**「浏览器动态读取」，而是「三种产物形态任选，从一条命令或一个文件开始」：

| 形态 | 命令/产物 | 场景 | 环境要求 |
|---|---|---|---|
| **① dev 预览** | `doclight dev` | 本地写作/预览（热重载） | 需 Node.js |
| **② SSG 发布** | `doclight build` → `dist/` | 公开发布、SEO | 需 Node 构建一次 |
| **③ bundle 便携包** | `doclight bundle` → `doclight.html` | 离线分发、双击即看 | **零依赖、跨浏览器** |

三者共享同一渲染内核，内容一致、无锁入。②③ 的产物是**已渲染的静态 HTML**，浏览器端只需展示，不做 Markdown 渲染（详见 [02-architecture](./02-architecture.md)）。bundle 形态已在 Chromium/Firefox/WebKit 三引擎 `file://` 下实测通过。

### 与竞品的定位差异

| 工具 | 零构建 | 阅读体验 | AI 友好 | 开源 | 定位 |
|---|---|---|---|---|---|
| **DocLight** | ✅ 核心 | ✅ 核心 | ✅ 核心 | ✅ MIT | 三者交集 |
| docsify | ✅ 核心 | ⚠️ 样式老旧 | ❌ 无 | ✅ MIT | 零构建轻量工具 |
| VitePress | ❌ 需构建 | ✅ 好 | ⚠️ 插件级 | ✅ MIT | Vue 生态 SSG |
| Starlight | ❌ 需构建 | ✅ 好 | ⚠️ 插件级 | ✅ MIT | Astro 生态文档主题 |
| MkDocs Material | ❌ 需构建 | ✅ 好 | ⚠️ 插件级 | ✅ MIT | Python 生态事实标准 |
| Docusaurus | ❌ 需构建 | ✅ 好 | ⚠️ 插件级 | ✅ MIT | React 生态重型框架 |
| Mintlify | ✅ SaaS | ✅ 设计极佳 | ✅ 核心 | ❌ 闭源 SaaS | AI 原生文档平台 |
| GitBook | ✅ SaaS | ✅ 编辑体验好 | ✅ 完整 | ❌ 闭源 SaaS | 平台型 docs-as-code |

### 目标用户

#### 主要用户（80% 精力）

| Persona | 描述 | 核心诉求 |
|---|---|---|
| **P1 个人开发者 / 开源维护者** | "只想 serve ./docs 里的 Markdown，别逼我学 React"；预算 $0 | 快、简单、离线可看、免费 |
| **P2 小团队技术负责人（2-15 人）** | 被 Mintlify $0→$300 定价悬崖挡在门外；要 docs-as-code | 零维护、好搜索、可自托管、性价比 |
| **P3 内容创作者 / 课程作者** | 做课程站、教程站、技术博客；要好看、要移动端友好 | 排版精良、零技术门槛、可离线分发 |

#### 次要用户（20% 精力）

| Persona | 描述 | 核心诉求 |
|---|---|---|
| **P4 自托管 / homelab 爱好者** | 数据自主、离线、无云依赖 | 可自托管、无外部依赖、数据安全 |
| **P5 技术写作者** | 非开发者，被 CI/CD 和文件夹结构折磨 | 编辑即发布、预览即时、结构清晰 |

### 不做的用户（明确放弃）

- 大型企业（需要 SSO/SOC2/合规审计——门槛太高，独立项目做不了）
- 需要复杂多版本管理的 API 文档（ReadMe/Mintlify 的主战场，竞争太激烈）
- 团队协作编辑场景（Notion/语雀/飞书的地盘，doc-as-code 路线不重合）

### 开箱即惊艳：默认模板策略

DocLight 的零配置承诺意味着**默认形态就是产品本身**。因此不是提供「一套主题 + 换色」，而是提供 4 套**完整的默认设计语言**：

| 模板 | 风格定位 | 目标人群 |
|---|---|---|
| **Minimal（默认）** | 极简灰阶 + teal 强调色 | 开发者 / 技术文档 |
| **Serif（学术）** | 衬线标题 + 米白纸感 | 课程站 / 知识库 / 论文 |
| **Modern（科技）** | 深色优先 + 轻玻璃拟态 | Startup / 产品文档 |
| **Warm（温暖）** | 暖色调 + 大圆角 | 教程 / 个人博客 |

- 每套都是完整视觉系统（排版、色彩、组件、动效），含亮/暗双主题
- `theme: "minimal"` 一行零配置切换
- 提供**主题预览对比页**（构建产物，Agent 与人都可直观对比）
- 模板质量由**视觉回归 + 设计合规检查**硬性验收（见 [10](./10-agent-dev-environment.md)），详细规格见 [11](./11-default-themes.md)

## 1.2 核心价值主张

### 对人：「打开就看，看完就走，不费脑子」

- **零安装零构建**：三形态任选——`doclight dev` 本地预览、`doclight build` 静态发布、`doclight bundle` 单文件便携包；从一条命令或一个文件开始
- **阅读体验极致**：精心调校的中文排版、舒适的视觉节奏、无干扰界面
- **搜索秒出**：内置全文搜索，Cmd+K 即搜即得，不依赖外部服务
- **离线可用**：bundle 便携包单文件双击即看，跨浏览器、无网络也能看（实测通过）

### 对 AI：「结构化、可预测、少黑盒」

- **机器可读**：llms.txt + docs.json + 语义 frontmatter，Agent 一眼看懂全站结构
- **MCP 原生**：完整的 MCP Server 实现，Agent 可以搜索、读取、导航、找示例
- **可定制**：JSON 配置 + 钩子插件 + 插槽系统，Agent 能轻松改造和扩展
- **无惊喜**：每个功能都有明确的接口和类型定义，Agent 不用猜

### 对开发者：「拿来就用，想改就能改」

- **零配置启动**：没有 config 文件也能跑，约定优于配置
- **渐进增强**：需要更多功能时再开，不用一开始就全套配置
- **无锁入**：内容是纯 Markdown，导出就是原始文件，随时可以迁走
- **MIT 协议**：最宽松的开源协议，商业使用无顾虑

### 对分享者：「内容被看到，传播零摩擦」

> 用户的底层动机不是「做文档站」，而是「让内容被理解、被信任、被传播」。部署是内容价值的兑现，分发是理解发生的最后一公里。完整设计见 [13-deployment-distribution](./13-deployment-distribution.md)。

- **一键部署**：`doclight build` + `doclight deploy` 一条命令上线，返回可用 URL
- **零部署分发**：bundle 单文件发给任何人，双击即看，无需对方安装任何东西
- **随处嵌入**：一键生成 iframe 代码，嵌进语雀/飞书/官网/博客
- **分享即传播**：自动生成 OG 分享卡片，链接发到微信/X 自带精美预览；默认「Powered by DocLight」形成口碑裂变
- **被 AI 发现**：llms.txt + MCP 让内容可被 AI 检索引用，多一个增长通道

## 1.3 设计原则

### 原则零：Agent-First（第一原则）

> 为 Agent 设计，而不是为人类开发者设计。几乎没有人手搓代码。

- **三类 Agent 都是用户**：开发本产品的 Code Agent、使用本产品的 AI Agent、与产品协作（扩展/定制）的 AI Agent
- 任何设计决策先问「Agent 能否理解、使用、修改它」，再问「人是否方便」
- 文档、错误信息、API、脚手架、CI 输出的**第一读者是 Agent**，其次才是人
- 「Agent 友好」不是加分项，是唯一的开发范式——它覆盖产品（使用端）与仓库（开发端）两个维度，开发端规格见 [10-agent-dev-environment.md](./10-agent-dev-environment.md)

### 原则一：内容是主角，工具是透明的

> 好的文档站让读者读完后记住了内容，记不起界面。

- 所有 UI 元素的存在都是为了辅助阅读，不是为了「好看」
- 装饰性元素为零——没有渐变、没有多余阴影、没有动效堆砌
- 强调色只用在真正需要引导注意力的地方（链接 hover、当前导航、搜索高亮）
- 阅读过程中，用户的注意力应该 100% 在文字和代码上

### 原则二：零构建优先，渐进增强

> 默认最简单，需要时再加。

- 零配置即可用（三形态任选：dev 预览 / SSG 发布 / bundle 单文件）
- 每一项高级功能都是 opt-in，不强制
- 学习曲线平滑：从「复制一句话给 Agent」到「完全定制」之间有很多中间步
- dev server 能做的事，绝不要求用户先 build

### 原则三：人阅读优先，AI 友好是天然副产品

> 清晰的结构、明确的语义，对人和对 AI 都好。

- 不是「为了 AI 加一层东西」，而是「把基础做扎实，AI 自然能用好」
- 语义化 HTML 对人（无障碍）和对 AI（理解结构）都有好处
- 清晰的文档组织对人（找得到内容）和对 AI（检索准确率）都有好处
- 人觉得好用的设计，往往 AI 也觉得好用

### 原则四：小而美内核 + 插件扩展

> 核心要小而牢，功能靠插件长出来。

- 浏览器展示层 < 25KB gzip，只做最本质的事（渲染在 Node 侧，见 02）
- 常用功能（搜索、高亮、mermaid）内置但可关闭
- 不常用功能做成插件，用户按需加载
- 插件 API 稳定、文档清晰、开发门槛低

### 原则五：Agent 可定制（从架构层设计）

> 不是加个聊天框叫 AI 友好，而是让 Agent 能像人一样使用和定制这个产品。

- 配置是纯 JSON，Agent 能读能写
- 插件有脚手架和明确的钩子，Agent 能写插件
- 主题是 CSS 变量，Agent 能精确控制外观
- 插槽系统让 Agent 能在正确位置插入内容
- 每一层 API 都有结构化文档和类型定义

### 原则六：无锁入

> 用户随时可以走，才会愿意留下来。

- 内容永远是纯 Markdown，不搞方言扩展
- 配置是标准 JSON，不是专有格式
- 导出就是原始文件，不需要专门的导出工具
- 不做 SaaS 锁定，不做数据绑架
- 迁移指南齐全（从 docsify / MkDocs / GitBook 迁入和迁出都容易）

## 1.5 命名说明

**DocLight** 这个名字的含义：
- **Doc** = Documentation，文档
- **Light** = 轻量、快速、明亮
- 读音和「doclight」一致，好记好拼
- ✅ npm 包名 `doclight` 已验证可用（2026-08 实测）；`doclite` 已被占用；`doc-light` / `lightdoc` / `marklight` 可用
- 域名可用性需后续确认（doclight.dev / doclight.xyz 等）

备选名：DocLite（npm 已占用）、LightDocs、MarkLight
