# 04 · 阅读体验设计

---

## 4.1 设计哲学：内容是主角

> 好的文档站不是「好看的 UI」，而是「让读者忘记 UI、专注内容」。
>
> 读完一篇文章后，用户记住了内容，记不起界面长什么样——这才是成功。

### 设计纪律

1. **单一强调色原则**：全站只有 1 个彩色（teal），其余全是灰阶
2. **零装饰原则**：每个视觉元素都必须有功能目的，纯装饰的一律砍掉
3. **克制动效原则**：动效只用在反馈和过渡上，不用来「炫」
4. **节奏优先原则**：排版的节奏（行高、段距、标题留白）比「好不好看」重要 10 倍

---

## 4.2 排版系统

### 4.2.1 正文字号与行高

**为什么是 16px / 1.75？**

中文排版研究表明：
- 字号 15-17px 是屏幕长文阅读的最佳区间
- 行高 1.7-1.8 对中文最舒适（英文 1.5 就够，中文因为笔画密需要更松）
- 16px × 1.75 = 28px 行高，正好是视觉舒适区

```css
.article {
  font-size: var(--font-size-base);  /* 16px */
  line-height: var(--line-height-relaxed);  /* 1.75 */
  max-width: var(--max-width-content);  /* 680px */
  color: var(--color-text);
}
```

### 4.2.2 行宽：680px 的科学

**38-42 个中文字符 = 一行一呼吸**

- 太宽（> 800px）：眼球横向移动距离大，容易串行，读完一行找下一行费劲
- 太窄（< 500px）：换行太频繁，打断思路，阅读速度下降
- 680px 在 16px 字号下约 38-42 个中文字符，正好是甜点区

**响应式调整**：
| 屏幕宽度 | 内容区宽度 | 字号 |
|---|---|---|
| < 640px（手机） | 100% - 32px 边距 | 15px |
| 640-1024px（平板） | 100% - 64px 边距 | 16px |
| > 1024px（桌面） | 680px 固定 | 16px |

### 4.2.3 标题层级（模块化缩放 1.25）

| 级别 | 字号 | 行高 | 上方留白 | 下方留白 | 字重 |
|---|---|---|---|---|---|
| H1（页面标题） | 2rem (32px) | 1.3 | 0 | 0.8em | 700 |
| H2（章节） | 1.5rem (24px) | 1.3 | 2.5em | 0.6em | 600 |
| H3（小节） | 1.25rem (20px) | 1.4 | 1.8em | 0.5em | 600 |
| H4（子节） | 1.1rem (17.6px) | 1.4 | 1.2em | 0.4em | 600 |
| 正文 | 1rem (16px) | 1.75 | - | 1em（段间距） | 400 |

**标题留白原则**：上方留白 > 下方留白。因为标题是「上一段的结束 + 下一段的开始」，更多的上方留白能强化章节感，让读者清晰感知到内容的分块。

### 4.2.4 段间距 vs 首行缩进

**现代 Web 阅读：段间距，不首行缩进**

- 首行缩进是纸媒传统，因为纸媒没有段间距的概念
- 屏幕阅读用段间距更清晰，视觉上有呼吸感
- 段间距 1.5em（约 24px），既区分段落又不太散

```css
.article p {
  margin: 0 0 1.5em;
  text-indent: 0;  /* 不首行缩进 */
}
```

### 4.2.5 字体栈

**正文（无衬线）**：
```css
--font-sans:
  "PingFang SC",           /* macOS / iOS：最佳中文渲染 */
  "Hiragino Sans GB",      /* 旧 macOS */
  "Microsoft YaHei",       /* Windows：最清晰的中文字体 */
  "Noto Sans CJK SC",      /* Linux */
  system-ui,
  -apple-system,
  "Segoe UI",
  Roboto,
  sans-serif;
```

**代码（等宽）**：
```css
--font-mono:
  "JetBrains Mono",        /* 最美观的编程字体（如已安装） */
  "SF Mono",               /* macOS */
  "Cascadia Code",         /* Windows */
  "Fira Code",
  ui-monospace,
  Menlo,
  Consolas,
  monospace;
```

**原则**：不引入 Web Font，用系统最好的字体。
- 零网络请求，不影响首屏速度
- 每个平台上都是原生质感（用户看惯了的字体）
- 不触发 FOIT（Flash of Invisible Text）

## 4.3 色彩系统

### 4.3.1 强调色：单一 teal

```css
--color-primary: #0d9488;       /* 主色：teal-600 */
--color-primary-hover: #0f766e; /* hover：teal-700 */
--color-primary-light: #ccfbf1; /* 浅色背景：teal-100 */
```

**为什么选 teal？**
- 中性、专业、不刺眼（不像红色热烈、不像紫色花哨）
- 技术感强（很多开发者工具用 teal/cyan 系）
- 明暗模式下都好看
- 眼睛疲劳度低（绿色波长短，对眼睛友好）

**使用纪律**：
✅ 链接 hover 态
✅ 当前导航高亮
✅ 搜索结果高亮
✅ 按钮/交互元素主色
✅ 进度条
❌ 大面积铺色
❌ 装饰性元素
❌ 正文文字（只用于强调关键词）

### 4.3.2 中性灰阶（8 级对称）

| 级别 | 亮色模式 | 暗色模式 | 用途 |
|---|---|---|---|
| 0 | #ffffff | #0a0a0a | 背景 |
| 1 | #f9fafb | #171717 | 次级背景（代码块、提示框） |
| 2 | #f3f4f6 | #262626 | 分隔线 / 边框（弱） |
| 3 | #d1d5db | #525252 | 边框（强） |
| 4 | #9ca3af | #737373 | 辅助文字（时间、标签） |
| 5 | #6b7280 | #a3a3a3 | 次要文字（目录、注释） |
| 6 | #374151 | #d4d4d4 | 正文 |
| 7 | #111827 | #f5f5f5 | 标题 / 重点 |

**设计要点**：
- 8 级灰阶够用了，太多反而造成选择困难
- 暗色模式的背景不是纯黑（#000），用深灰（#0a0a0a）更护眼
- 文字对比度严格遵循 WCAG AA 标准（正文 > 4.5:1，标题 > 3:1）

### 4.3.3 语义色（克制使用）

只在需要语义传达的场景使用，且只占小面积。

| 颜色 | 值（亮） | 值（暗） | 用途 |
|---|---|---|---|
| 成功 / 通过 | #059669 | #10b981 | 成功提示、正确示例 |
| 警告 / 注意 | #d97706 | #f59e0b | 警告提示、注意事项 |
| 错误 / 危险 | #dc2626 | #ef4444 | 错误提示、危险操作 |
| 信息 / 提示 | #2563eb | #3b82f6 | 信息提示、普通说明 |

## 4.4 内容元素细节设计

### 4.4.1 代码块

```
┌─ 复制按钮（hover 时才显示） ────┐
│                                    │
│  function hello() {                │
│    console.log("Hello, World!")    │
│  }                                 │
│                                    │
└────────────────────────────────────┘
  语言标签（可选）
```

**设计要点**：
- 背景：比正文背景深一级灰（不突兀但能区分）
- 圆角：6px，跟整体风格统一
- 内边距：16px 20px
- 字号：0.875rem（14px），行高 1.6
- 横向滚动：溢出时可以左右滑
- 滚动提示：右侧渐隐效果，提示还有更多内容
- 复制按钮：hover 时才显示在右上角，不打扰阅读
- 行号：可选，默认关闭（减少视觉噪音）

### 4.4.2 行内代码

```css
.article code {
  font-family: var(--font-mono);
  font-size: 0.875em;
  padding: 2px 6px;
  background: var(--color-bg-code);
  border-radius: 4px;
  color: var(--color-primary);  /* 用强调色，让代码词在正文中醒目 */
}
```

注意：行内代码用强调色可以提升技术文章的可读性——代码关键词在正文中一眼就能看到。

### 4.4.3 引用块

```
│  这是一段引用文字。
│  引用的内容通常是别人说的话，
│  或者是需要特别注意的内容。
```

**设计**：
- 左侧 3px teal 竖线
- 左内边距 16px
- 文字颜色降一级（次要文字色）
- 字号跟正文一样（不变小）
- 不改变字体（不用楷体/斜体，保持阅读节奏）

### 4.4.4 提示框（自定义容器）

四种类型：Tip / Note / Warning / Danger

```
💡 提示
这是一条提示信息。

ℹ️ 注意
这是一条注意事项。

⚠️ 警告
这是一条警告信息。

🚫 危险
这是一条危险操作提醒。
```

**实现**：通过 Markdown 自定义容器语法
```markdown
:::tip 提示
这是一条提示信息。
:::
```

**设计要点**：
- 左侧彩色竖条（对应语义色）
- 背景是浅色调（亮模式）/ 深色调（暗模式）
- 图标 + 标题在左上角
- 内容跟正文同字号同颜色
- 圆角 6px

### 4.4.5 表格

- 只有横向分隔线（没有竖线，更简洁）
- 表头背景深一级
- 斑马纹：可选，默认关闭（减少视觉噪音）
- 溢出时横向滚动，左侧/右侧有渐隐提示
- 数字列右对齐，文本列左对齐

### 4.4.6 图片

- 最大宽度 100%，不超出内容区
- 圆角 6px
- 自动居中（单独一行的图片）
- `loading="lazy"` 懒加载
- 点击放大（lightbox，可选插件）
- 有 alt 文本的图片，下方显示图注

### 4.4.7 链接

**常态**：与正文同色，无下划线
**Hover**：teal 色 + 下划线
**访问过**：不改变颜色（避免视觉混乱）

```css
.article a {
  color: inherit;
  text-decoration: none;
  border-bottom: 1px solid transparent;
  transition: color var(--transition-fast), border-color var(--transition-fast);
}

.article a:hover {
  color: var(--color-primary);
  border-bottom-color: var(--color-primary);
}
```

**为什么常态无下划线？**
- 技术文章里链接多，满篇下划线会严重干扰阅读
- hover 才显示下划线，既不影响阅读又有明确反馈
- 外部链接加个小图标（↗），暗示会跳走

## 4.5 交互细节

### 4.5.1 滚动体验

**锚点跳转偏移**：
```css
/* 标题上方留 80px 空间，防止被顶栏挡住 */
.article h2[id], .article h3[id] {
  scroll-margin-top: 80px;
}
```

这是一个很多文档站都没做好的细节——点击目录跳转到标题，结果标题被顶部导航栏挡住了。

**平滑滚动**：
```css
html { scroll-behavior: smooth; }
```

但只在 `prefers-reduced-motion: no-preference` 时启用，尊重用户系统设置。

### 4.5.2 页面切换过渡

- 内容区 150ms 淡出 → 加载 → 150ms 淡入
- 不是整页刷新感，也不是花哨的动画
- 快、轻、不抢戏

### 4.5.3 阅读进度

- 顶部细线进度条（高度 2px，teal 色）
- 右侧 TOC 导轨同步高亮当前章节
- 不显示百分比数字（没有必要，增加视觉噪音）
- 进度条只在滚动时显示，停止滚动后渐隐

### 4.5.4 回到顶部

- 滚动超过 2 屏后出现
- 右下角，小圆形按钮（40px）
- 透明度 0.7，hover 时 1.0
- 点击平滑滚动到顶部
- 移动端与 TOC 按钮合并

### 4.5.5 专注模式

- 点击按钮或按快捷键（`Ctrl/Cmd + .`）
- 隐藏侧边栏和 TOC
- 内容区居中，宽度可保持或放大
- 让读者专注于内容本身
- 再按一次恢复

### 4.5.6 字号调节

- 三档：小（14px）/ 中（16px，默认）/ 大（18px）
- 顶部栏 A- / A+ 按钮
- 记忆到 localStorage
- 行高自动同步调整（小号 1.7，大号 1.8）

## 4.6 无障碍设计（A11y）

### 4.6.1 键盘导航

- 所有可交互元素可通过 Tab 键访问
- 清晰的 focus ring（不是默认的丑 outline，是自定义的 teal 色 2px 环形）
- 搜索框：`Cmd/Ctrl + K` 打开，`Esc` 关闭，↑↓ 导航，Enter 打开
- 侧边栏：方向键导航节点
- 全局快捷键帮助：`?` 显示快捷键列表

### 4.6.2 屏幕阅读器

- 语义化 HTML 结构（`<header>`, `<nav>`, `<main>`, `<article>`, `<aside>`）
- 所有图标按钮有 `aria-label`
- 图片有 `alt` 文本
- 动态内容变化有 `aria-live` 通知
- 跳转链接（跳到主内容）

### 4.6.3 色彩对比度

- 正文对比度 ≥ 4.5:1（WCAG AA）
- 大文本（≥ 18px/粗体）≥ 3:1
- 强调色在亮/暗模式下都验证对比度
- 不仅靠颜色传达信息（错误 = 红色 + 图标 + 文字）

### 4.6.4 减少动效

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation: none !important;
    transition: none !important;
    scroll-behavior: auto !important;
  }
}
```

尊重用户的系统设置，有前庭功能障碍的用户不会被动画干扰。

## 4.7 打印样式

专门的 `@media print` 样式，让用户打印出来也是好看的。

- 隐藏所有导航、搜索、按钮、交互元素
- 内容区全宽，无边距限制
- 链接显示 URL（`content: attr(href)`）
- 代码块换页不截断
- 黑白优化（去掉彩色，用灰度区分）
- 页眉显示文档标题，页脚显示页码和 URL

## 4.8 响应式设计

### 断点设计

| 断点 | 设备 | 布局变化 |
|---|---|---|
| < 640px | 手机 | 侧边栏收起（按钮拉出），TOC 变底部面板，内容区全宽 |
| 640-1024px | 平板 | 侧边栏可折叠，TOC 可选显示，内容区自适应 |
| 1024-1440px | 小桌面 | 侧边栏 + 内容 + TOC 三栏布局 |
| > 1440px | 大桌面 | 三栏居中，两侧留白，内容区不无限拉宽 |

### 移动端特别优化

- 顶栏高度 48px（适合手指点击）
- 按钮最小尺寸 44×44px（iOS 规范）
- 字体大小自动调整（`text-size-adjust: 100%`）
- 触摸反馈：按下时背景微变暗（替代 hover 态）
- 双击缩放禁止（内容区不需要，避免误操作放大）
- 安全区域适配（`viewport-fit=cover` + `safe-area-inset`）
