# 08 · 部署运维与安全：产品怎么可靠地跑

> **核心问题**：Agent 产品上线不是「一个 API 部署」——runtime 进程、会话数据、成本、安全都要管理。这一篇是产品从「能跑」到「能运营」的分界线。
> **四问框架**：dsh 给了什么 → 你要做什么 → 怎么做 → 常见坑。
> **交叉引用**：运行时细节见 `../sdk-docs/09-边界限制与FAQ.md`；并发模型见 `../sdk-docs/08-集成模式实战.md` 场景 3；安全机制见 `../deepseek-harness-解析.md` §3.1。

---

## 1. dsh 给了什么（运行时基础设施）

| 资产 | 作用 |
|---|---|
| 惰性启动 + 复用 | 子进程常驻，跨调用复用 |
| 关闭阶梯 | shutdown → EOF → SIGTERM → SIGKILL（不泄漏） |
| 多会话/多实例 | 状态隔离与并行的两种手段 |
| JSONL/SQLite 持久化 | 会话数据落盘、可恢复 |
| 沙箱策略 | danger-full-access / workspace-write / landlock |
| 凭据引用 | apiKeyEnv 模式（值不进配置） |
| 协议版本号 | serverInfo.version（升级信号） |

**关键认知**：dsh 给了「运行机制」，产品要做的是**容量、成本、安全、升级**的运营决策。

## 2. 你要做什么：五个运营决策

### 2.1 运行时生命周期（预热与复用）

```
部署形态：
  - 单例 harness（进程级）      → 轻量产品、串行任务
  - 实例池（N 个 harness）      → 并发需求：池化 + 借还
  - 每租户实例                  → 安全隔离要求

预热策略：
  - 应用启动时 start()（消除首个请求延迟）
  - 实例池按水位预热/回收
  - 长任务超时 → 外部监控 + 关闭重建（SDK 无 mid-turn cancel）
```

### 2.2 并发架构（两种并行，算清楚账）

| 方式 | 机制 | 成本 | 适用 |
|---|---|---|---|
| 单实例多会话 | 状态隔离、执行串行 | 1 进程 | 任务排队可接受 |
| 多实例 | 真并行 | N 进程线性增长 | 并发硬需求 |

**容量估算**：`并发任务数 × 单任务时长 = 需要多少实例`。长任务（研究型）→ 实例数少但每实例忙很久；短任务（问答）→ 实例可共享。

### 2.3 成本控制

```
三层预算：
  ① 单请求：max_tokens（SDK 参数）
  ② 单任务：你的编排层预算（步数/轮次上限——Python 循环或 workflow caps）
  ③ 全局：实例池水位 + 每日 token 看板 + 告警

监控（事件流 usage 字段）：
  - 每会话 token 趋势 → 发现失控会话
  - 每任务成本分布 → 发现贵任务（多半是流程设计问题：缺验证、多绕路）
```

### 2.4 安全（产品侧清单）

| 项 | 做法 |
|---|---|
| 沙箱模式 | 生产用 `workspace-write` 起步；`danger-full-access` 只许一次性容器（官方原话） |
| 凭据 | 全部 `apiKeyEnv` 环境变量；**模型进程不得见生产密钥**（dsh 凭证机制照抄） |
| 多租户 | `session_root`+`cwd` 分目录；高风险上进程隔离 |
| 注入防御 | 工具权限最小化 + 危险操作审批 + 出站白名单（课程 07 章纵深防御） |
| 审计 | 事件流全量落库（05 篇）；不可变存储 |
| stdout 纪律 | 自定义组合里禁止 stdout logger（协议信道污染） |
| 故障注入演练 | 每季度：投毒工具返回、诱导删测试、静默失败（课程 07 章 Lab） |

### 2.5 升级管理

dsh 是开发者预览（v0.1.0-rc.5，无兼容承诺）——**升级是产品风险**：

```
升级流程：
  1. 锁版本（pip/npm 精确版本）
  2. 变更检查：serverInfo.version 变化 → 协议可能变
  3. 冒烟测试：握手 + 一次真实 run + 会话恢复 + 关键工具
  4. 灰度：先一个实例，跑你的评估集（07 篇），再全量
  5. 回滚预案：版本降级 + 会话数据兼容性检查（SESSION_FORMAT_VERSION）
```

## 3. 怎么做：部署检查清单（上线前逐项过）

```
□ 沙箱模式已按环境配置（dev=full-access 容器 / prod=workspace-write）
□ 凭据全部走环境变量，无硬编码；模型进程无生产密钥
□ 实例池预热完成，启动延迟已消除
□ 关闭路径验证（无子进程泄漏：压力测试后进程数回落到基线）
□ 会话数据备份/归档策略生效（JSONL 目录）
□ 成本三层预算已配置，token 看板有告警
□ 审计落库在跑（事件流→审计存储），抽样验证数据完整性
□ 升级流程文档化（锁版本+冒烟+灰度+回滚）
□ 故障注入演练至少跑过一轮（投毒/超时/崩溃恢复）
□ 多租户隔离验证（租户 A 会话不可见租户 B 数据）
```

## 4. 常见坑

| 坑 | 后果 | 解法 |
|---|---|---|
| 不关 harness / 泄漏子进程 | 内存与进程爆炸 | with/await using + 关闭验证 |
| danger-full-access 直接上线 | 数据事故 | 生产环境换 workspace-write + 演练 |
| 无成本预算 | 一张意外大账单 | 三层预算 + 看板告警 |
| 长任务无外部监控 | runtime 卡死无人知 | 任务级超时 + 关闭重建 |
| 版本漂移（升级不验证） | 协议破坏、会话读不了 | 锁版本 + 冒烟 + 灰度 |
| stdout 污染（自定义组合） | 协议信道坏、行为诡异 | 组合自查 + stdout 冒烟测试 |
| 会话数据不备份 | 数据丢失 | JSONL 目录进备份策略 |
| 认为「SDK 会自动清理」 | 会话无限堆积 | 归档/清理策略（04 篇） |
